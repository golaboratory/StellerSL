# バッジの仕様

## コンセプト

ソーシャルゲームの「ログインボーナス」「デイリーミッション」「アチーブメントシステム」を参考に、ユーザーが TODO 管理において **「小さな達成感」を短いスパンで得られる** ように設計する。

### 設計原則

1. **初日に3つ獲れる** — 開始直後の「褒められ体験」でドーパミンを発生させる
2. **毎週なにか新しい** — 1週間使えば少なくとも1つは新しいバッジに出会う
3. **途切れても戻れる** — 連続記録の喪失による離脱を「カムバック系バッジ」で吸収する
4. **遊び心で驚かせる** — 時間帯・曜日・季節に連動したバッジで「予想外の喜び」を提供する
5. **長期のやり込みに報いる** — 累積系・レア系でベテランユーザーの満足感を維持する

### キャラクター成長との連動

- タスク完了 → **10 EXP**、100 EXP ごとにレベルアップ (`level = (exp / 100) + 1`)
- レベルに応じてキャラクターが自動進化:

| レベル | キャラクター | アイコン |
|--------|------------|---------|
| 1〜4   | たまご (egg) | pi-circle |
| 5〜9   | ひよこ (chick) | pi-twitter |
| 10〜19 | にわとり (chicken) | pi-heart |
| 20+    | フェニックス (phoenix) | pi-bolt |

## モチベーション維持のための仕組み

### 1. 初期の報酬ドロップ率を高くする

開始から3日間で3〜5個のバッジがサクサク獲れるように設計:
- **1日目:** `first_task` → `three_strike`（3タスク完了するだけで2個）
- **2日目:** `rookie_planner`（5タスク登録）、`daily_runner_bronze` への途中経過表示
- **3日目:** `daily_runner_bronze`（3日連続達成）、`task_crusher_1` に近づく

### 2. 「惜しい！」の可視化（プログレス表示）

バッジ獲得までの進捗をゲージ表示:
- 「7日連続達成まであと1日！」
- 「累計100個まであと5個」
- 「金曜日にあと2タスクで **フライデーフィニッシャー** 獲得！」

> **実装方針:** フロントエンドでバッジ条件と現在の統計値を比較し、達成率80%以上のバッジを「もうすぐ」としてハイライトする。

### 3. シークレットバッジによるサプライズ

- 獲得条件が隠された「???」バッジを一覧に表示
- 予想外のタイミングで獲得通知が出る喜び（ランダム報酬効果）
- SNS共有を意識したバッジデザイン（将来的に共有機能追加時に活用）

### 4. 「喪失感」の緩和

- **カムバックヒーロー** で「いつ再開してもウェルカム」を演出
- **不死鳥の翼** で「何度でも戻ってきていい」を強化
- ストリークが途切れても過去の最長記録（`max_count`）は保持し、「以前は○日連続を達成した」と表示

### 5. バッジ剥奪ルール

| カテゴリ | 剥奪 | 理由 |
|---------|------|------|
| 累積系（task_crusher等） | done→他に戻すと再評価 | タスク完了数が閾値を下回れば剥奪 |
| 時間系（early_bird等） | 永続 | 時間帯の行動は事実として変わらない |
| ストリーク系（daily_runner等） | 永続 | 過去の連続達成の事実は変わらない |
| シークレット系 | 永続 | サプライズ報酬の剥奪は心理的ダメージが大きい |

## 実装優先度

### Phase A（実装済み — 19種）
上記表の [実装済] バッジすべて。engine.go + 07_badges.sql に反映済み。

### Phase B（実装済み — 10種）
- `first_project`, `first_team_join`（導入系の補完）
- `daily_runner_platinum`（ストリーク上位）
- `monday_motivator`, `friday_finisher`（曜日系）
- `lightning_fast`, `lunch_hustler`, `golden_hour`, `hat_trick`（タイム系拡充）
- `zero_inbox`（プロジェクト系の実用的バッジ）
- engine.go + 07_badges.sql + migrations/000007 に反映済み。全種別のユニットテストは `engine_test.go` を参照

### Phase C（チーム・ソーシャル系 — 3種）
- `team_builder`, `mentor`, `leaderboard`
- チーム機能の利用率が上がった段階で投入

### Phase D（シーズン＆シークレット — 11種）
- イベント系5種 + シークレット系6種
- 長期運用フェーズで段階的に追加

### Phase E（やり込み・上位 — 4種）
- `task_crusher_legend`, `phoenix_return`, `weekend_warrior`, `grand_master`
- アクティブユーザーが増えた段階で投入
