## Project Overview

StellerSL is a multi-tenant TODO/task management app with gamification (badges, character leveling). Built with a Go backend (Huma) and Vue 3 frontend, orchestrated via Docker Compose.

## Commands

### Start development environment
```bash
docker-compose up          # starts PostgreSQL, backend (port 8888), frontend (port 5173)
```

### Backend
```bash
cd backend && go test ./...                          # run all backend tests
cd backend && go test ./internal/api/task/...        # run tests for a single package
cd backend && sqlc generate                          # regenerate DB access layer from sql/
```

### Frontend
```bash
cd frontend && pnpm install                          # install dependencies
cd frontend && pnpm dev                              # dev server
cd frontend && pnpm build                            # production build (vue-tsc + vite)
cd frontend && pnpm vitest run                       # run unit tests
cd frontend && pnpm vitest run tests/auth.spec.ts    # run a single test file
cd frontend && pnpm test:e2e                         # Playwright E2E tests
cd frontend && pnpm test:e2e:ui                      # Playwright E2E with UI
```

### API client regeneration (run with backend up)
```bash
./generate-api.sh          # Unix
.\generate-api.ps1         # Windows PowerShell
```

## Architecture

### Schema-driven development cycle
1. Edit SQL in `backend/sql/query.sql` or `backend/sql/schema.sql` -> run `sqlc generate` -> generates `backend/internal/db/`
2. Implement/update Huma endpoint in `backend/internal/api/<domain>/`
3. Run `generate-api.sh` (backend must be running) -> regenerates `frontend/src/api/`
4. Build UI using the generated type-safe Axios client

### Auto-generated code (do NOT edit manually)
- `backend/internal/db/` — generated by sqlc from `backend/sql/`
- `frontend/src/api/` — generated by OpenAPI Generator from the backend's `/openapi.json`

### Backend structure (`backend/`)
- `cmd/main.go` — entrypoint
- `internal/api/api.go` — route registration hub
- `internal/api/<domain>/` — handler, service, model per domain (auth, project, task, team, dashboard, gamification)
- Each domain follows: `handler.go` (Huma operations) + `service.go` (business logic) + `model.go` (DTOs)
- `sql/schema.sql` — full DDL; `sql/query.sql` — all sqlc queries; `sql/migrations/` — incremental migrations

### Frontend structure (`frontend/`)
- Vue 3 Composition API with `<script setup>`, TypeScript, Tailwind CSS v4, PrimeVue 4
- `src/views/` — page components; `src/stores/` — Pinia stores (auth, toast); `src/router/` — Vue Router with auth guards

### Multi-tenancy
- Tenant resolved from HTTP `Host` header (or `X-Tenant-Host` override) via `GetTenantByDomain` query
- All tables carry `tenant_id` (UUID); PostgreSQL RLS enforces isolation
- Default tenant UUID `00000000-0000-0000-0000-000000000001` used for localhost

### Authentication
- JWT-based; passwords hashed with bcrypt
- Frontend stores token in localStorage via Pinia; Axios interceptor handles 401 refresh

### Gamification
- 10 EXP per completed task, 100 EXP per level (`level = (exp / 100) + 1`)
- Badge system with automatic awarding based on achievements

## Database

- PostgreSQL 16 (Docker); connection string via `DB_URL` env var
- Init scripts in `_initdb/` run automatically on first `docker-compose up`
- Soft delete pattern on tasks (`deleted_at` timestamp)
- UUID primary keys (`gen_random_uuid()`)
